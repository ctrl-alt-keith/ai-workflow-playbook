# CAK-67 First-Pass Architecture Proposal

Status: pre-implementation proposal for independent review

## Decision Surface

Generalize Playbook startup for meaningful AI collaboration while preserving
the detailed repository workflow and avoiding a new summary document that
duplicates existing doctrine.

## Selected Architecture

Use the three-layer model as an ownership lens, not as a mandatory document
taxonomy.

1. `docs/core-model.md` remains and becomes the canonical owner of compact,
   domain-independent AI operating principles. It already owns human/AI roles,
   authority, semantic phase boundaries, durable continuity, validation, and
   scope discipline, so adding a second operating-principles document would
   split one conceptual owner. Keep the addition to one concise section of no
   more than nine bullets and roughly 60 lines; link to mechanism owners rather
   than adding subordinate taxonomies or procedures.
2. `docs/start-here.md` becomes the compact, task-neutral routing entry point.
   It owns startup selection and the minimum invariant index, not the detailed
   principles or workflow mechanisms.
3. Existing workflow documents retain their mechanism ownership:
   `source-first-retrieval.md` for source-trigger detection and repository
   retrieval mechanics; `evidence-lifecycle.md` for evidence acceptance and
   semantic accounting; `feature-lifecycle.md` for proportional proposal-first
   repository delivery and post-merge reconciliation; `review-packet.md` and
   `external-ai-reviewer.md` for independent review and finding disposition;
   `repo-readiness.md` and `engineering-baseline.md` for repository execution;
   executor adapters for executor-specific deltas.
4. Repository and provider mechanics remain conditional hydration. Meaningful
   work that depends on current sources, a consequential action, or a bounded
   workflow reads `start-here.md` and `core-model.md`; repository work then
   reads the repository route and local authority. Ordinary general chat,
   brainstorming, and conceptual discussion do not acquire a startup or live
   retrieval requirement. Specialized documents remain trigger-selected rather
   than unconditional.

## Planned File Surface

- `docs/core-model.md`: add one compact canonical operating-principles section,
  capped at nine bullets and roughly 60 lines, with explicit links to mechanism
  owners.
- `docs/start-here.md`: restructure as a general startup router with a compact
  startup contract, general path, repository path, conditional hydration, and
  existing instruction hierarchy.
- `docs/tool-adapters/codex.md`: narrow startup deltas so they explicitly build
  on the canonical general principles rather than appearing to own them.
- `README.md`: update the repository map and scope wording for the new ownership.

Do not change `AGENTS.md`, `source-first-retrieval.md`, lifecycle mechanisms,
review semantics, repository isolation, validation, or PR requirements in this
pass. Existing repo-family `AGENTS.md` references continue to enter through
`start-here.md` and therefore do not require a rollout edit.

## Critique Before Implementation

- Abstraction leak: avoid making Git, worktrees, PRs, planning systems, or
  repository trigger taxonomies appear universal in `core-model.md`.
- Duplicated ownership: principles must link to mechanism owners and must not
  restate trigger lists, finding taxonomies, validation classes, or lifecycle
  sequences.
- Accidental doctrine: label every scope promotion above in the PR, including
  widening `start-here.md` from repository startup to meaningful AI work that
  depends on current sources, consequential action, or a bounded workflow;
  preserve proportionality and avoid mandatory ceremony or startup obligations
  for ordinary chat, brainstorming, or conceptual discussion.
- Weakened repository semantics: retain the complete repository read order,
  instruction hierarchy, source-first rule, interaction-mode preflight,
  worktree/branch/validation/PR path, final review, integrated identity, and
  post-merge reconciliation.
- Excessive hydration: only `core-model.md` is unconditional after
  `start-here.md` for meaningful bounded work; ordinary chat and brainstorming
  remain outside this contract, and specialized docs load from triggers.
- Unnecessary document: reject a new `operating-principles.md` because
  `core-model.md` already owns the same conceptual layer.

## Rejected Alternatives

1. Make `start-here.md` the canonical owner of all principles: rejected because
   routing and doctrine ownership would be conflated and startup would grow.
2. Add `docs/operating-principles.md`: rejected because it would overlap
   `core-model.md` and create two general operating-model owners.
3. Generalize `source-first-retrieval.md` wholesale: rejected because its
   trigger taxonomy and evidence hierarchy are intentionally repository and
   software oriented; the general invariant can be owned separately without
   weakening those mechanics.
4. Reorganize all workflow docs into three directories: rejected because the
   ownership problem does not require a filesystem taxonomy or broad rewrite.
