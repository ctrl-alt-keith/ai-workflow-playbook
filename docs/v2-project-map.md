# v2 Project Map

This is the arc-level map for CAK-301. It does not define "v2 complete" or
authorize an implementation, default, Product, release, or retirement change.
For the accepted semantic foundation, see
[v2-architecture-foundation.md](v2-architecture-foundation.md); for the
qualified opt-in slice, see [v2_retain/README.md](../v2_retain/README.md).

## Current state

The v2 semantic foundation is accepted, and one qualified integrated,
opt-in implementation slice exists. The v1/default bootstrap remains current.

## Active arc

Dogfood real workflow seams. The current leading candidate is **conditional
consequential authority / changed-head merge sequencing**. It is a candidate
experiment, not a committed roadmap item.

## Next arcs

1. Let repeated, concrete dogfood needs earn reusable mechanisms.
2. Earn default-v2 for a defined scope through the four gates below.
3. Later, shrink v1 by responsibility until retirement becomes boring.

## Progress accounting: 4 gates before default-v2 for a defined scope

This is a boundary count, not a task count or a claim that v2 is otherwise
complete. The four gates are:

1. scope/inventory;
2. qualified coverage;
3. migration/operator evidence; and
4. separately authorized and verified cutover.

Unless later evidence makes them necessary, the count excludes additional
providers, reboot or power-loss durability, Product-status promotion, release
machinery, every possible dogfood experiment, and eventual v1 retirement.

## Deferred / usage-driven work

Keep mechanisms, providers, and broader operational work deferred until a
repeated concrete need earns them. In particular, do not infer a universal
runtime, a large migration program, a new Product identity, or a definition of
"v2 complete" from this map.

## v1 retirement direction

Retire v1 by responsibility, not filenames or strings. Ask: **If this vanished
today, what supported behavior or recoverability would we lose?** Retain live
and compatibility responsibilities, archive historical-only material, and
delete only after verified replacement plus rollback/recovery review. Preserve
the pre-v2 archive tag as the historical safety anchor; do not modify it.

## Guiding constraints

- Earn it before building.
- Keep architecture acceptance, implementation integration, default-bootstrap
  cutover, release/operational adoption, Product status, and v1 retirement as
  distinct boundaries.
- Use role and semantic language in reusable documentation; reserve identity
  and locality details for necessary provenance.
