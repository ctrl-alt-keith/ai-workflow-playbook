# Optional Upstream-Change Review

Use this only when a local owner wants to learn from an upstream playbook. It
does not make upstream authoritative or require synchronization.

1. Keep a durable review checkpoint that says only: "reviewed upstream through
   here."
2. When useful, inspect upstream changes since that checkpoint using an
   available source.
3. Let a human decide which ideas, if any, fit locally.
4. Advance the checkpoint only after that review.

A checkpoint does not claim local correspondence, adoption, or a shared
architecture. Git commits, file versions, dates, or links can identify a
checkpoint when useful; none is required. Derivative or fork maintenance is a
separate, narrower local concern and should be added only when it earns a
place.
